## 「含斜杠 git 引用无法创建」—— 最终结论：agent 沙箱伪影，非缺陷

起因：用 ask-matt 回答「下一步该干什么」，复查 M2 DAG 时发现 05 的阻塞条件存疑。

### 中途的错误定性（已推翻，保留以免重蹈）

我一度判定为「D 盘环境级缺陷」，依据：本仓库路径下 `git branch task/x` /
`git update-ref refs/heads/a/b` / `git tag t1/x` 静默失败（退出码 0 无 ref），
`git worktree add -b task/x` 报 `fatal: invalid reference`；而同一仓库 clone 到 C 盘
临时目录全绿、D 盘全新空仓库也红。据此把 05 的 blockers 改成 `02, 08`。
**这个定性是错的**，盘符只是表象。

### 真正的变量：沙箱

反馈循环脚本 `.scratch/m2-implementation/repro-08.mjs`（同时建带斜杠和不带斜杠
两个分支做对照，0=GREEN / 1=RED）。关键实验：同一条命令、同一仓库、同一 git 二进制，
连续跑三遍（A 工作区内 → B 工作区外 → 再 A）：

- 命令被提权（输出带 `Sandbox bypassed` 横幅）→ 三次全 GREEN；
- 命令在沙箱内 → 全 RED（slashed NOT created，但 control 分支建得出来）。

git 二进制不是变量：PortableGit 2.55.0.windows.3 与系统 Git 2.51.0.windows.2
在同一沙箱状态下结论一致。bash 的 `mkdir -p` 不受影响，所以手工建目录看不出问题；
git 需要「先建子目录、再在新目录里建文件」，被沙箱文件系统层拦掉。
C 盘临时目录不拦、D 盘工作区拦 —— 这个差异把我误导到了「D 盘卷属性」方向。

## 环境坑位补充

- 给 git.exe 传 `/d/...`、`/tmp/...` 这类 MSYS 路径会被当成 Win32 字面路径解析
  （`git clone /d/code/x` 报 "does not exist"，还会在 `D:\d\...`、`C:\tmp\...` 造残留目录）。
  给 git 传盘符路径要写 `D:/code/...`，目标路径尽量用相对路径。
- 判断命令是否在沙箱里：看输出有没有 `Sandbox bypassed` 横幅；
  `dangerouslyDisableSandbox: true` 不 reliably 触发提权（实测仍可能留在沙箱内）。

## agent-manager 集成测试：InputResolved 丢弃语义 + 陈旧构建陷阱

- `input:resolve` 在 `discard` 时由 service 层（`packages/agent-manager/src/service.ts` INPUT_RESOLVE handler）
  **发出一个 `InputResolved` 归一化事件并落库一次**，跨进程重启后仍存在且恰好 1 条；
  同时把 input 状态置 `DISCARDED`、`uncertainInputs` 清空。
- storage 层的 `resolveInput(id,'discard')` 只翻转 input 状态（→`DISCARDED`），**不**发事件；
  发事件是 service 层职责。两条 new 测试都正确：`event-recovery.mjs`（DB 层）与
  `agent-manager.cjs` 第 200–202 行（集成层，断言 `InputResolved` 恰好 1 条）。
- 文档口径一致：`release-gates.md:151`（不重发不确定输入）、`coding-agent-workbench-mvp.md:72`（不确定输入要求用户处理、不自动重放）。
- **踩坑**：`release-evidence/failure-injection/process.log` 报告第 202 行
  「丢弃决定只持久化一次」`0 !== 1`，但那是**陈旧构建**产物——该日志 mtime(21:13:54)
  早于 `out/main/agent-manager.js` 的重新构建(21:16)。未提交改动给 service.ts 加了 InputResolved
  发射逻辑，但 `out/` 当时没重建，于是测试跑的是没发 InputResolved 的旧 bundle。
- 修复/验证手段：先 `npm run build` 重建 `out/`，再用聚焦 Electron 集成脚本（只跑
  seed→discard→restart→数 InputResolved，绕开沙箱 git worktree 斜杠引用伪影）确认
  `InputResolved count: 1`、重启后 `uncertainInputs: 0`。结论：**断言本身已与当前语义一致，无需改测试；
  失败根因是陈旧构建，重建即过。**
- 完整 `test-agent-manager.mjs` 在沙箱内无法跑通（line 69 `git worktree add -b task/<id>` 被沙箱拦），
  与本次 bug 无关；用户真机（非沙箱）上用新构建跑全量套件即可。
